# Voice Action Lab frontend

Japanese React + TypeScript single-page client. All interface graphics are original inline SVG/CSS. No external fonts, assets, credentials, recordings, or run exports are included.

## Parent workspace integration

- Install dependencies from the root workspace. This package does not manage the root lockfile.
- Vite is pinned to **8.2.2**, the highest published stable version checked on 2026-09-17, rather than the `latest` tag pointing at `8.3.0-beta.1`. React and React DOM are pinned to **19.3.0**; `@vitejs/plugin-react` **6.1.1** supports Vite 8.
- TypeScript, Node types, and browser-test tooling come from the root workspace (`typescript`, `@types/node`, `@playwright/test`).
- Use the parent's Node 24 environment. No `VITE_*` variable or browser-side service credential is required; deployment/model/region configuration stays on the server.
- Run `npm run dev --workspace @voice-action-lab/web` for port **5173**.
- The Vite development server proxies `/api` HTTP and WebSocket traffic to **http://127.0.0.1:3000**, matching the server's default IPv4 loopback binding and avoiding `localhost` resolving to IPv6 upstream.
- For local development, the parent configures the server's comma-separated `ALLOWED_ORIGINS` to include **http://localhost:5173** and **http://127.0.0.1:5173**. Include **http://127.0.0.1:3000** too when using the built same-origin SPA. Example development value: `http://localhost:5173,http://127.0.0.1:5173,http://127.0.0.1:3000`. These are server settings, not browser secrets or Vite variables. Keep production origins exact and HTTPS-only; do not disable Origin validation or use a wildcard.
- Run `npm run typecheck --workspace @voice-action-lab/web`, `npm run build --workspace @voice-action-lab/web`, and `npm test --workspace @voice-action-lab/web`.
- Run `npm run test:browser --workspace @voice-action-lab/web` after the parent installs dependencies and a Playwright browser is available. Tests own a temporary Vite server on port **5175** and mock every API/WebSocket interaction with synthetic fixtures; the application backend is not needed. Traces, video, and screenshots are disabled, and test output goes to the operating-system temporary directory, not the repository.
- `PLAYWRIGHT_CHANNEL=msedge` (or `chrome`) selects an already-installed browser instead of bundled Chromium. `PLAYWRIGHT_OUTPUT_DIR` optionally selects an explicit **outside-repository** temporary test output location.
- `PLAYWRIGHT_BUILT_CLIENT=1` runs browser tests against the existing production build using Vite preview; build first. HTTP/WS remain mocked. This also checks that the emitted AudioWorklet bundle actually loads, not just the development module.
- Build output is `apps/web/dist`. Production hosting must serve the built client and proxy the same-origin `/api` endpoints, including WebSocket upgrades. `vite preview` is not a production API proxy.

## Contract and server expectations

The client imports types from [the shared contract](../../packages/contracts/index.ts) without modifying it. HTTP responses and WebSocket snapshots are runtime-validated. Only the requested routes are used:

| Method | Route | Use |
| --- | --- | --- |
| GET | `/api/config` | Live availability and disabled-button reason |
| GET | `/api/state` | Initial and reconnected state |
| WebSocket | `/api/events` | Authoritative `BrowserState` snapshots |
| POST | `/api/simulation/start` | Explicit simulation start `{ mode }` |
| POST | `/api/command` | Simulation-only `GameCommand` |
| POST | `/api/stop` | Global stop `{}` |
| POST | `/api/session` | Server SDP exchange `{ mode, sdp }` |
| POST | `/api/session/ready` | Attach trusted server sideband after peer connection and datachannel open; `{}` returns `BrowserState` |
| POST | `/api/session/close` | Release the live session `{}` |
| POST | `/api/activity` | Live-only audio activity `{ offsetMs }`; requires `{ ok: true }` |

- Authentication is same-origin/server-managed. HTTP 401/403 are presented explicitly.
- Enforce single-session ownership, session expiry (at most ten minutes), and stale-start cancellation on the server too. A browser cannot guarantee network delivery or timers in a suspended/closed tab. Close must invalidate any in-progress SDP startup or sideband attachment even if its HTTP client timed out.
- `/api/session` must return the SDP answer without waiting for sideband attachment. Attaching before the browser peer connects can return 404 and deadlock the exchange. `/api/session/ready` performs that attachment later and must return an active live `BrowserState` in the selected mode on success.
- Stop is available in every startup phase. Before ready succeeds, the client still releases tracks/peer and aborts event waits immediately, posts `/api/stop`, drains pending SDP/ready startup requests, and then posts `/api/session/close`. Late permission or ready results cannot restart media.
- After **ready has succeeded**, stop immediately disables microphone **and remote** tracks without ending them, pauses PCM measurement in that same synchronous turn, mutes/detaches playback, and posts `/api/stop` so the authoritative engine stops without waiting for the usage handshake. The established peer/datachannel and capture tracks remain alive until `/api/stop` followed by `/api/session/close` settles; only then are they released. Stale connected snapshots cannot re-enable the muted tracks.
- Established media has an independent **20-second close grace timer**. If the server has not acknowledged by then, local media is forcibly released with a visible warning. Cleanup HTTP requests retain their individual 20-second timeouts; ownership/start controls stay locked until those issued requests settle, preventing a late cleanup from racing a new start. Errors remain visible/retryable. No client event or success flag manufactures `final_usage_confirmed`: `final_usage_unconfirmed` remains the server's reported result.
- Component unmount uses the same close path and defers closing its owner state WebSocket during established cleanup. Cleanup POSTs use `keepalive`. Actual navigation/tab/process termination can still destroy browser transports before acknowledgement; this is best effort and cannot guarantee confirmed usage.
- A reconnecting WebSocket is **not** proof that WebRTC recovered. State-feed loss disables commands/start and marks positions stale, but never fabricates a new game.
- `session.expiresAt` controls the visible countdown; starts also have a local ten-minute ceiling. This absolute cap must still close the run even while audio or work is active.
- The approved idle policy is **90 continuous seconds with no user audio, no assistant audio, and no processing**. Server-side `queued`/`running` operations, in-flight backend work, backend activity, and audio activity notifications from either speaker must prevent an idle stop. This is not a user-only inactivity timer. The server owns the monotonic, run-relative idle clock and enforcement.
- Idle warnings arrive in the existing `session.message`, which the UI displays. Optional future `session.idleWarning: string` is also recognized, but no contract extension is required. The client does not run its own 90-second inactivity timer. Activity notifications supplement, rather than replace, authoritative server-side audio/work tracking.
- Event `kind` is preserved visibly. Basic categories recognize speech/audio/transcript, operation/move, cancel/interrupt, and commit names. Event timestamps are server-relative, not browser audio-stop measurements.

## Media lifecycle and recording

- Live startup order is strict: user gesture -> `getUserMedia` -> **disable the captured microphone track** -> add the track and `oai-events` -> local offer/description -> wait for **complete ICE gathering (8 seconds maximum)** -> send the final `localDescription.sdp` to `/api/session` -> apply the remote answer -> wait for **peer connected AND datachannel open (25 seconds maximum)** -> POST `/api/session/ready` `{}` -> validate active live `BrowserState` -> **enable the microphone**.
- Sideband attachment is triggered by native peer/datachannel readiness, not by waiting for a server-connected snapshot. A WebSocket snapshot alone cannot enable the microphone while `/api/session/ready` is pending. The ready request runs once per connection; failure or cancellation never enables the mic or switches to simulation.
- SDP HTTP exchange is bounded to 30 seconds; the ready HTTP request uses the normal 20-second API timeout. ICE/transport waits remove listeners/timers on completion, timeout, or disposal. A late ready response after stop is ignored, and server close follows that in-flight attachment.
- Incoming audio is played through an audio element from remote media tracks, never synthesized from JSON. Autoplay failures offer an explicit retry button.
- The first microphone device ID is reused for sequential A/B runs within the page. If that device disappears, connection fails explicitly rather than switching microphones.
- `session.*_transcript.delta` text is optional ephemeral UI only. It is bounded in memory and cleared for the next run; it is not an audio timing probe.
- **One AudioContext per live attempt** measures microphone and received PCM together, using a two-input AudioWorklet with silent output. Context creation/resume begins in the connect gesture. Worklet initialization is bounded to eight seconds before SDP setup; missing/blocked worklets fail explicitly, never fall back to transcript metrics. Optional encoded recording borrows this same context and does not close it when recording stops.
- The silent measurement context requests `latencyHint: "playback"` to give the render thread more buffering headroom than the low-latency interactive default. This is a browser hint, not a scheduling guarantee; it does not change the WebRTC microphone or the separate incoming-audio playback element. It can delay measurement delivery, so these metrics remain received-PCM observations, not audible playback latency. A forward render-frame gap resets both partial windows and hysteresis without resetting their clock or sequence; metadata explicitly records `paused` then `measuring` and the UI warns that the trial's voice latency is missing. The missing frames are never replaced with silence or joined into an apparent stop. Backward frames and invalid PCM remain fatal, with a fixed processor failure and frame delta displayed.
- The worklet accumulates energy, not PCM history, in fixed **20 ms** windows across native render quanta. RMS is the square root of mean channel power; opposite-phase stereo cannot cancel the measurement. Threshold is **−45 dBFS**, exactly `10 ** (-45 / 20)`. **Three consecutive above-threshold windows** confirm activity, **six consecutive below-threshold windows** confirm silence. The processor retains only sums/counters; PCM is never posted to the page, persisted, or exported. Fractional frame boundaries are rounded cumulatively, avoiding sample-rate drift.
- Activity reporting starts only after `/api/session/ready` succeeds and pauses with transport readiness loss. Both sources share one `performance.now()` anchor captured at the live connect attempt, never `Date.now()`. Only strictly increasing integer `{ offsetMs }` values in 0–600000 are posted, at most once per two seconds with one request in flight (at most 30/minute, below the shared 240 mutation/minute budget). **These notifications contain no audio or transcripts**; normal live microphone audio still goes through WebRTC to the voice service.
- Notification HTTP requests time out after five seconds; malformed acknowledgements, auth/network failures, or suspended/failed measurement are visible errors and close the voice session rather than silently continuing with unreliable idle protection. Stop/failure/unmount pauses measurement and aborts activity requests in the same turn as muting media. Worklet/context cleanup follows the established close acknowledgement or grace deadline, while negotiating attempts clean up immediately. Queued measurement packets are ignored after pause, so software mute is not reported as an observed PCM stop transition. New attempts replace the in-memory metadata log. Only explicit local JSON export persists redacted metadata; no automatic upload/storage exists.
- Optional recording combines microphone and remote streams into a **local** `MediaStreamAudioDestinationNode`. It does not connect the microphone to speakers. Recording starts only with consent, stops on disconnect, and is bounded to 64 MB. Download is a browser blob URL created after stop; no recording/upload route exists.
- Audio, transcripts, and download URLs are not persisted across reloads. A pending recording download must be discarded before starting another recording.
- Received PCM activity is **not proof of physical speaker playback**: autoplay/device latency and mute still matter. Transcript timing is never substituted. Closing the context during active audio does not invent a confirmed silent transition; a six-window confirmation must actually be observed.

## Automated experiment measurement contract

Listen on `window` for **`voice-action-lab:audio-measurement`** before clicking the real connect button. This is a data-only `CustomEvent`; there are no global control functions, credentials, or command listeners. Imported/replayed data never emits this event.

- Every `detail` has `version: 1`, a browser-local opaque `measurementId` (not a server run/session ID), and a `type`.
- `type: "anchor"` is emitted after ready succeeds, before measurement starts. It includes `sampleRate`, `windowMs: 20`, `thresholdDbfs: -45`, `activeWindows: 3`, `silentWindows: 6`, and `clockAnchor: { contextTime, performanceNowMs }`.
- `type: "sample"` includes `direction: "input" | "output"`, a per-direction increasing `sequence`, `windowStartTime`, `contextTime` (window **end**), linear `rms`, `aboveThreshold`, debounced `active`, `transition: "start" | "stop" | null`, `transitionTime`, and `clockAnchor`.
- **All context times are seconds in the same AudioContext.** Each sample's `clockAnchor.contextTime` is `AudioContext.currentTime` read on main-thread delivery, paired with `performance.now()` in `clockAnchor.performanceNowMs`. The two directions in one worklet message share this exact pair. For alignment, estimate a context time `t` on the performance clock with `anchor.performanceNowMs + (t - anchor.contextTime) * 1000`; main-thread delivery time is not the audio window time.
- `transitionTime` is the start of the first window in the confirmed streak; `contextTime` is confirmation time, **60 ms / 120 ms later** for start/stop (within sample-frame rounding). Use only confirmed transitions or the actual window samples. Do not interpret an unconfirmed tail or missing samples as silence.
- `type: "status"` includes `status: "measuring" | "paused" | "closed" | "error"` and `clockAnchor`. Readiness loss pauses measurement; resume resets hysteresis/partial windows and retains sequence/context clock. Late packets from older readiness generations are ignored. A new A/B attempt has a new context and measurement ID; the microphone selection remains the same.
- Samples are retained only in browser memory (at most 60,000 windows across both directions, plus bounded lifecycle metadata). The runner may collect event details privately; no raw PCM or transcripts are in these events. Engine event clocks/pacing remain server-owned and need independent runner alignment.

Production must serve the emitted `audioMeasurement.worklet-*.js` as JavaScript on the same origin, with CSP allowing that worklet module. Vite emits it next to the main bundle, not in an assets directory. Rebuilding changes hashed filenames; reload static-route registration as needed. No cloud `/api/exports` integration is included.

## Local export and readonly imports

After stopping, explicitly prepare/download `voice-action-lab-local-session-v1.json`. Its root is `{ format: "voice-action-lab.local-session", version: 1, snapshot, measurements }`. `snapshot` uses the BrowserState shape but replaces server run/operation/call/delegation identifiers, removes all event details, allow-lists event kinds (others become `redacted`), and removes session messages/expiry/recording flags. Source, mode, final cargo positions, operation status/timing, and safe event structure remain. `measurements` contains exactly the versioned event details above. Neither recorded audio nor transcripts are included.

Import uses a local file reader, not HTTP. Local measurement archives reject unknown keys/versions, unredacted state, malformed/nonfinite/out-of-order clocks, mixed measurement IDs, invalid window/transition durations, invalid cargo positions, and oversized data: **32 MiB UTF-8**, 62,048 measurement records, 2,000 operations, 10,000 events, and at most ten minutes of sampled time. A still-active session cannot be exported as a stopped session.

Replay plays/scrubs **activity metadata or saved server events**, next to the explicitly labelled **saved final snapshot**. It neither reconstructs cargo history nor plays sound, fires live measurement events, starts a connection, or sends actions upstream. Missing PCM windows display “サンプルなし”, not invented silence. Imported data is labelled local/unverified, not live evidence. Import/replay is disabled during a live/simulation run; a new run pauses replay and replaces the retained live metadata. Reload/discard releases browser memory and blob URLs.

### Server RunExport v1 compatibility

The same file picker also accepts downloaded server documents from `GET /api/exports/:runId`, without calling that API itself. [parseReplayDocument](src/localSession.ts) auto-detects the local `format` or server `schemaVersion: 1`; [parseLocalSession](src/localSession.ts) remains local-format-only.

Server input is exactly `{ schemaVersion: 1, runId, source, closedAt, exportedAt, game, session, usage, settings }`. **`source` is top-level**; **`session` has only `{ transport: "disconnected" | "error", recording: false }`**. Missing `session.source/message/expiresAt` is expected, not an error. The reader builds an internal display-only BrowserState from these fields, preserving source, final game, and error/disconnected status. It does not assign that state to the live session hook.

- Server documents use their own **2 MiB UTF-8**, **3,000 operation**, and **20,000 event** limits. UUID/run matching, stopped game state, identifiers, settings bounds/models, optional full `sourceCommit`, and parseable dates are validated using the existing browser-state/record/number guards. Unknown fields, raw audio/transcripts, arbitrary strings/nested payloads in event details, active sessions, and incompatible versions are rejected. Only the server's safe primitive details and enumerated public strings are accepted.
- `usage.scope` must be `voice-session-only`. `confirmed` plus numeric metrics must match the last `final_usage_confirmed` event; a later `final_usage_unconfirmed` requires `unconfirmed` and null metrics. Simulation requires `not-applicable` and null metrics. Contradictory claims are rejected, not silently upgraded or assigned zero usage. The UI labels usage as **file-reported**, not independently verified.
- `settings.sourceOffsetsSynchronized` must be false. Settings are displayed only; they never change live mode, engine pacing, auth, or session limits.
- Server exports have **no PCM windows**. The UI states this explicitly and offers a recorded-event timeline instead of fabricating measurements. Events are displayed in recorded timestamp order (sequence breaks ties), relative to the first event. They are never dispatched to the engine/API, and event timing is never promoted to audible-stop timing.
- Cloud create/download/delete controls and authentication compatibility remain parent-owned. No `/api/exports` requests, credentials, imported actions, or live measurement events are generated by import/replay.

## Validation

The native-audio browser suite uses one worker, matching the application's single-live-session scope. Run it separately from CPU-heavy builds/unit suites: competing browser audio contexts can miss render deadlines on a shared host. Such loss is deliberately missing measurement evidence, not a reason to fabricate continuous samples or retry a formal trial. Multi-worker runs are optional resource-stress tests, not the default deterministic CI gate.

[API tests](src/api.test.ts) use explicitly synthetic fixtures only and Node's built-in runner. They cover contract validation, auth errors, malformed/network responses, exact request shapes, and absence of a live-error simulation fallback.

[WebRTC wait tests](src/webrtc.test.ts) use event targets and controlled timers to verify the exact eight-second gathering and twenty-five-second connection limits, both-state readiness, failure, and cancellation.

[Activity tests](src/audioActivity.test.ts) verify monotonic offsets and notification bounds. [PCM tests](src/pcmWindow.test.ts) verify exact 20ms/-45dBFS/3-on/6-off behavior, multi-rate frame boundaries, stereo energy, pause, and invalid PCM. [Local format tests](src/localSession.test.ts) verify redaction, limits, hostile input and replay gaps. Browser tests use native worklets with synthetic tones to verify both directions, ready gating, context sharing with opt-in recording, event anchors, local JSON download/import, no upstream replay, silence/transcripts, cancellation and explicit failures. No real audio or run data is saved.

[Browser tests](tests/lab.spec.ts) cover source labelling, disabled live availability, sequential mode locking, authoritative positions, exact simulation replacement commands, invalid state, microphone denial, late permission after emergency stop, server expiry, optional idle warning, narrow viewport overflow, and reduced motion. Synthetic WebRTC cases verify fully gathered SDP, peer-plus-channel ordering, disabled microphone until sideband success, exact startup timeouts, failed/late sideband attachment, cancellation during gathering/SDP/ready, and reuse of the same microphone for sequential A/B startup.

These tests exercise client behavior with synthetic transports; they are **not** evidence of real audio quality, audible interruption, or Azure live integration. Real acceptance requires the parent-configured service, actual microphone permission, incoming media playback, and separate A/B runs. Validate protocol cancellation against server commits independently from actual audio-stop measurements; keep recordings and measurement exports outside the repository.

Stop-order regressions hold both server acknowledgements to verify immediate mute/game-stop request, retained peer/datachannel/live tracks, ignored stale connected state, preservation of `final_usage_unconfirmed`, and the exact 20-second local grace deadline. Startup/late-permission/late-ready abort cases remain separate. The parent's real synthetic-media generator must keep sending continuous frames (including silence); these mocked-transport browser tests do not establish RTP continuity or real semantic cancellation.

For the parent's standalone browser live probe, use the built same-origin application (for example `http://127.0.0.1:3000`), or the Vite application on port 5173 with its backend proxy targeting **http://127.0.0.1:3000**. To bind the Vite listener explicitly to IPv4, run `npm run dev --workspace @voice-action-lab/web -- --host 127.0.0.1` and open `http://127.0.0.1:5173`; the server allowlist above covers both development origin spellings. The built application uses relative `/api` URLs on its own origin and does not use the Vite development proxy. Do not use `about:blank` or the mocked test harness on port 5175. Synthetic microphone media may replace physical input, but the real-integration probe must retain the native peer, actual SDP exchange, and actual backend/WebSocket routes. The regular browser suite intentionally mocks those boundaries and cannot validate ICE connectivity or the deployed model.

Bearer-authenticated automation requires the **built client**. The [browser helper](../../scripts/experiment-browser.ts) fetches its same-origin hashed worklet bundle through the authenticated page and loads those unchanged bytes from a temporary Blob URL, because direct worklet requests can bypass Playwright's page-level extra headers. It accepts only the measurement asset path, HTTP 200 and JavaScript MIME, with a five-second/256-KiB limit and no redirects. The URL is revoked after loading; code, tokens and PCM are not persisted. Ordinary cookie-authenticated UI loading is unchanged. No server authentication or CSP is relaxed, and a policy blocking Blob worklets fails explicitly. This adapts script loading only: PCM processing, native WebRTC, SDP and backend routes are not mocked.
